# UI / UE 审查与分阶段验收

基线：2026-09-28，`main` 的当前 Web 工作台。范围为 `src/routes/`、`src/lib/components/{mail,shell,ui}/`、`src/app.css`、`DESIGN.md` 和现有 Playwright 流程。本审查只描述仓库中可见的实现；真实邮件与生产环境不属于 UI 验收证据。

## 现状与问题

| 维度 | 已有基础 | 待解决问题 |
| --- | --- | --- |
| UI 架构 | `+page.svelte` 组合邮箱状态，`mail/`、`shell/`、`ui/` 已分层；SvelteKit 路由和服务端 API 分离；域名与地址有独立导航视图 | `+page.svelte` 仍同时处理列表、详情、草稿、搜索、标签、批量操作和布局，状态依赖密集 |
| 组件复用 | Button、IconButton、Dialog、Drawer、DropdownMenu、表单、状态、空态和骨架屏均有共享组件 | 写信的地址 chip、附件操作和管理页部分按钮仍手写样式；相同状态的 hover、focus 与触控尺寸容易漂移 |
| UX | 支持多发件身份、草稿自动保存、批量选择、搜索、专注阅读和安全 HTML 展示；跨文件夹星标与持久化标签已有独立服务端视图，当前页所选邮件可批量添加/移除标签 | 混合文件夹的归档、已读和移入垃圾箱仍不开放；大规模邮箱与浏览器兼容性仍需独立验收 |
| 布局 | 桌面三栏、侧栏折叠、可调整列表宽度和移动端单面板都已存在；域名与地址已从设置页分离 | 设置页资料、通知和诊断仍是连续长表单，已增加分区跳转和固定保存入口；小屏下写信的高级 HTML 区和附件区会显著拉长滚动距离 |
| 可维护性 | `DESIGN.md` 已定义颜色、字号、间距、主题、响应式和可访问性约束 | 新功能需要继续拆分 `+page.svelte` 的领域状态；设计规范与实际新增交互需同步，避免文档宣布功能而代码尚未实现 |

## 分阶段工作

1. 写信主流程：最近联系人补全；让高级 HTML 默认收起，并把附件和 HTML 选项放在固定操作区；桌面浮动窗口支持拖动、缩放、最小化和最大化，同时保留键盘焦点与草稿安全。
2. 导航与身份管理：明确区分文件夹、全局星标、标签、域名、地址和设置。跨文件夹视图需要服务端分页与计数，不能把当前页筛选伪装成全局结果。
3. 阅读与列表：逐项核对长正文、长主题、大附件、多域名/多地址和批量操作；邮件多时再按测量结果考虑虚拟列表。
4. 完整验收：1920、1440、1366、768、390 px；浅色与深色；Chromium、WebKit、Firefox；键盘、焦点、可访问名称、对比度和屏幕阅读器。Linux WebKit 模拟不等同于真实 Safari。

第 1 阶段已落地联系人补全、写信操作区整理和桌面浮动窗口。建议来源限于当前浏览器会话已加载的收件/已发送邮件，去重后排除用户自己的受管地址；它不是全量通讯录，也不把联系人写入本地存储。其余事项仍须按上述范围实现和验证。

导航与管理进展：域名概览、邮箱地址管理和设置已拆成三个可直达的导航状态；域名卡片已增加收信/发信能力汇总，按现有路由、地址状态和发送门禁保守判断，检查证据过期时提示复核而非宣称真实投递。地址创建仍复用原有受管身份 API，未把域名配置或供应商状态检查改成自动写操作。全局星标已新增独立的 Owner 范围服务端分页、计数、搜索和地址筛选，收件、归档、已发送与草稿均在范围内。标签现可创建、重命名、删除和应用到邮件，D1 `0027` 保存 Owner 标签及邮件关联；标签视图按服务端跨文件夹分页。邮件详情中的新建标签会直接应用于当前邮件；标签工具栏和表单复用共享控件。标签批量操作现可在收件、已发送、归档、星标和标签视图针对当前页明确勾选的邮件添加/移除标签，服务端先验证每封邮件的 Owner 与未删除状态，再在一个 D1 batch 中提交；草稿和入站邮件分别按自身类型校验。混合文件夹的归档、已读和移入垃圾箱仍不开放，避免误用单文件夹作用域。以上仅有本地 D1/浏览器证据，不代表远程 D1 已迁移或生产已发布。

批量标签验收：Bun 集成测试覆盖四类来源的事务写入、重复目标去重、其他 Owner 与已删除邮件拒绝、超出 100 条限制及无部分增删；隔离本地 Chromium 桌面/390 px 手机经 UI 全选、逐封勾选、添加新标签、移除其中两封并刷新复核。弹窗在 390/320 px 均不越过视口，320 px 操作改为逐行全宽；Escape 关闭后将焦点还给发起按钮，浅色/深色弹窗通过 axe WCAG 2.1 AA 自动扫描。隔离本地 WebKit 桌面/iPhone 验证收件与草稿混合选择的批量移除，Firefox 桌面验证收件与已发送混合选择的批量添加及刷新后持久性；这些浏览器引擎测试不等于真实 Safari 设备测试。截图位于 `/tmp/flaremail-labels-bulk-{desktop,mobile}.png`、`/tmp/flaremail-labels-bulk-dialog-{desktop,mobile}.png`、`/tmp/flaremail-labels-bulk-dialog-narrow.png`、`/tmp/flaremail-webkit-bulk-label-{webkit-desktop,webkit-iphone}.png` 和 `/tmp/flaremail-firefox-bulk-label-dialog.png`。这不等于真实屏幕阅读器或生产 D1 验证。

设置页资料草稿现在按字段保留未保存编辑：其他标签页的身份变更触发会话刷新时，只同步未编辑字段；保存成功后显示服务端规范化结果。隔离本地 D1 的双标签页 Chromium 桌面与移动端回归均已覆盖这一行为。

设置长表单现有资料、通知、外观、诊断和 Telegram 分区链接；使用原生锚点，键盘可进入，滚动时导航与保存栏保持可见，跳转不卸载未保存字段。移动端改为工作区内部滚动并约束容器宽度，避免导航把页面撑宽，也让全局顶栏留在视口中。临时通知在设置页上移，不覆盖保存栏。隔离本地 Chromium desktop/mobile 已验证跳转位置、草稿保留、键盘激活、深色主题、无横向溢出和 axe 主区域扫描；截图位于 `/tmp/flaremail-settings-sections-{desktop,mobile}.png` 与 `/tmp/flaremail-settings-appearance-dark-{desktop,mobile}.png`。这些不是完整屏幕阅读器或真实设备证据。

设置页分区交互还通过了隔离本地 WebKit desktop/iPhone/iPad 与 Firefox 的回归：锚点跳转后标题不被导航遮住、保存入口留在视口、未保存姓名保持不变；Firefox 覆盖 1920/1440/1366/768/390 px。截图位于 `/tmp/flaremail-settings-webkit-{webkit-desktop,webkit-iphone,webkit-ipad}.png` 和 `/tmp/flaremail-settings-firefox-{1366,390}.png`。Firefox 首次运行因测试容器禁止 user namespace 且 XDG/dconf 目录只读，在浏览器启动阶段超时；将 XDG 缓存、配置和运行目录指向 `/tmp` 并为该容器禁用 Firefox 内容沙箱后重跑通过。这些仍是 Linux Playwright 模拟结果，不等同于真实 Safari、实体设备或屏幕阅读器验收。

图标操作进展：共享 `IconButton` 已接入可悬停、可键盘聚焦的 Tooltip，保留直接作用于按钮的 accessible name，并用稳定的服务端/客户端 ID 关联提示。浏览器截图曾发现顶部提示被顶栏遮挡、中文被压成竖排、移动端返回提示超出视口；现按工具栏/列表/写信底栏及视口边缘设置方向与内容宽度，并用端到端几何断言防止回归。顶栏搜索宽度规则也已收窄到搜索组件根节点，避免影响清除按钮。

写信的 To/Cc/Bcc 收件人 chip 已归入同一邮件组件，移除操作统一使用带 Tooltip 的 `IconButton`，保留字段和邮箱的无障碍名称及手机 44 px 触控目标。共享 Tooltip 现在只允许一个提示处于待显示或显示状态，避免指针留在写信窗口关闭图标时再用键盘聚焦移除图标出现双提示。隔离本地 Chromium 桌面/手机的写信与图标引导回归、WebKit iPhone 的 To/Cc/Bcc 草稿及附件 smoke 均通过；手机视觉截图位于 `/tmp/flaremail-compose-recipient-tooltip-mobile.png`。这些不代表真实 Safari 或完整屏幕阅读器验收。

写信窗口进展：桌面使用不锁定工作区的浮动写信窗口，可拖动、键盘调整位置和尺寸、最小化与最大化；手机保持全屏。草稿与附件状态属于写信组件，不因最小化销毁。仍需覆盖跨浏览器、极端窗口尺寸和更多焦点序列。

手机写信概念稿 `docs/design-concepts/flaremail-mobile-compose.png` 与最新 390 px 截图已并排检查：白色表面、蓝色主操作、地址 chip、正文留白和底部固定操作区保持同一视觉语言；标题位置、收件人行密度、抄送/密送入口、保存状态和底部按钮排列仍有明显差异。当前额外的发件身份选择是多域名发送所需，不应为贴图移除；其余差异属于后续手机写信布局优化范围，本轮 chip/Tooltip 修复不构成概念稿的完整视觉验收。

手机写信布局已随后按概念稿收敛，并以 390×844 px 的隔离本地 Chromium 截图 `/tmp/flaremail-compose-layout-mobile.png` 回看：标题居中、左侧关闭、简短保存状态、收件人 chip、抄送/密送分隔行、主题行、开放正文及底部三按钮都已接近参考；正文内容和空白长度取决于测试草稿。差异仍有：标题保留“新邮件/回复/转发”等真实模式而非固定“写邮件”；多域名必需的发件地址行保留且长地址会截断；右上角未添加无对应功能的省略号；高级 HTML 与附件管理仍在正文之后，底栏提供快捷入口。收件人地址过长或有多个地址时允许换行，不能为了视觉稿裁掉真实收件人。320×720 px 的本地 Chromium 草稿回归亦通过，截图 `/tmp/flaremail-compose-layout-narrow.png` 显示底部按钮均在视口内，页面无横向溢出。隔离本地 WebKit iPhone 的 To/Cc/Bcc、附件上传、草稿恢复 smoke 通过；这些仍不等于真实 Safari 或屏幕阅读器验收。

后续首屏复查发现收起的高级 HTML 区仍露在 390 px 正文下方；已调高手机正文最小高度，让高级区和附件区留在滚动内容中。底栏 HTML 图标展开选项后会把标题滚入写信窗口；隔离本地 Chromium 手机测试对标题可见几何与草稿恢复再次通过。长正文、多个附件和软键盘弹出时的真实设备滚动仍待专项验收。

浏览器验收进展：Firefox 桌面隔离 D1/R2 smoke 的 7 项已通过，覆盖收件阅读、邮件标签持久化、第二发件身份写信，以及域名页在 1920/1440/1366/768/390 px 的浅色和深色布局。WebKit 桌面、iPhone、iPad 的七项 smoke 均已各自连续通过，涵盖导航/搜索/阅读、安全 HTML、写信/草稿/假发送、主题及交互语义。这些是 Linux Playwright 模拟证据，不等于真实 Safari 或生产邮件验证。完整屏幕阅读器、极端内容和真实设备验收仍待完成。

极端内容进展：Firefox 隔离 smoke 已覆盖约 450 字符的超长主题、400 行正文，以及手机宽度上传、模拟发送和下载 7 MB 附件的完整路径；1366/768/390 px 无页面级横向滚动。写信底栏现在显示已就绪附件数量，附件大小按 B/KB/MB 展示，长主题展开控件文字更清晰。仍需在其他浏览器、真实设备以及更多特殊邮件内容上复核，不能将这组 smoke 视为全部极端场景验收。

附件计数复核：手机写信底栏与桌面浮动窗口分别使用可见的计数徽标和稳定的屏幕阅读器状态区域。Firefox 390 px 的 7 MB 本地附件流程现在断言手机徽标确实可见、附件按钮关联正确的状态说明，并扫描含附件写信窗口的 WCAG 2.1 AA 自动规则；不再把隐藏的桌面徽标当作手机证据。真实屏幕阅读器播报仍须设备实测。

视觉比对进展：以 1505×1045 的本地 Chromium 截图对照 `docs/design-concepts/flaremail-desktop-workspace.png`。三栏结构、白色内容面、蓝色写信入口、淡蓝选中态和橙色品牌色保持一致。概念稿的侧栏/列表约为 240/447 px，当前为 232/440 px；顶栏从 50 px 增至 64 px，仍比概念稿约 74 px 更紧凑；桌面邮件行从约 76 px 增至 88 px，仍比概念稿约 98 px 更密集。顶栏搜索现居中且有最大宽度，右侧账号改为仅头像入口，保留可访问名称和菜单。合成测试邮件的内容、额外导航项和详情中安全 HTML 控件与概念稿不同；真实 Safari、屏幕阅读器及完整视觉忠实度仍未获证实。

阅读附件复核：此前 `AttachmentList` 在桌面固定两列，只有一个附件时也只占半个阅读栏；现在所有尺寸都以整行卡片呈现，并缩短卡片纵向内边距。隔离 Chromium 桌面 1505×1045 与移动视口的浏览器断言均确认附件行宽等于列表宽度，安全 HTML、CID、远程图片同意及报告下载路径保持通过；截图分别位于 `/tmp/flaremail-attachment-desktop.png` 和 `/tmp/flaremail-attachment-mobile.png`。

工作区高度复核：桌面顶栏增至 64 px 后，工作区仍按旧的 50 px 扣减视口高度。现在顶栏和工作区共用 `--fm-desktop-topbar-height`，1505×1045 的浏览器断言确认工作区底边与文档高度均不越过视口；手机继续使用独立的 52 px 顶栏与安全区规则。
