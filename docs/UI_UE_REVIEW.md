## 分阶段工作

1. 写信主流程：最近联系人补全；让高级 HTML 默认收起，并把附件和 HTML 选项放在固定操作区；桌面浮动窗口支持拖动、缩放、最小化和最大化，同时保留键盘焦点与草稿安全。
2. 导航与身份管理：明确区分文件夹、全局星标、标签、域名、地址和设置。跨文件夹视图需要服务端分页与计数，不能把当前页筛选伪装成全局结果。
3. 阅读与列表：逐项核对长正文、长主题、大附件、多域名/多地址和批量操作；邮件多时再按测量结果考虑虚拟列表。
4. 完整验收：1920、1440、1366、768、390 px；浅色与深色；Chromium、WebKit、Firefox；键盘、焦点、可访问名称、对比度和屏幕阅读器。Linux WebKit 模拟不等同于真实 Safari。

第 1 阶段已落地联系人补全、写信操作区整理和桌面浮动窗口。建议来源限于当前浏览器会话已加载的收件/已发送邮件，去重后排除用户自己的受管地址；它不是全量通讯录，也不把联系人写入本地存储。其余事项仍须按上述范围实现和验证。

导航与管理进展：域名概览、邮箱地址管理和设置已拆成三个可直达的导航状态；域名卡片已增加收信/发信能力汇总，按现有路由、地址状态和发送门禁保守判断，检查证据过期时提示复核而非宣称真实投递。地址创建仍复用原有受管身份 API，未把域名配置或供应商状态检查改成自动写操作。全局星标已新增独立的 Owner 范围服务端分页、计数、搜索和地址筛选，收件、归档、已发送与草稿均在范围内。标签现可创建、重命名、删除和应用到邮件，D1 `0027` 保存 Owner 标签及邮件关联；标签视图按服务端跨文件夹分页。邮件详情中的新建标签会直接应用于当前邮件；标签工具栏和表单复用共享控件。标签批量操作现可在收件、已发送、归档、星标和标签视图针对当前页明确勾选的邮件添加/移除标签，服务端先验证每封邮件的 Owner 与未删除状态，再在一个 D1 batch 中提交；草稿和入站邮件分别按自身类型校验。星标/标签视图还可对明确选中的非草稿邮件跨收件、归档和已发送执行已读/未读、星标/取消星标与移入垃圾箱；全为收件时可归档或移回收件箱。服务端重新校验 Owner、地址范围以及星标或标签成员关系，不扩展会话；含草稿的选择会明确提示只支持批量标签，避免静默跳过。以上仅有本地 D1/浏览器证据，不代表远程 D1 已迁移或生产已发布。
