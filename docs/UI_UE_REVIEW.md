# UI / UE 审查与分阶段验收

基线：2026-09-28，`main` 的当前 Web 工作台。范围为 `src/routes/`、`src/lib/components/{mail,shell,ui}/`、`src/app.css`、`DESIGN.md` 和现有 Playwright 流程。本审查只描述仓库中可见的实现；真实邮件与生产环境不属于 UI 验收证据。

## 现状与问题

| 维度 | 已有基础 | 待解决问题 |
| --- | --- | --- |
| UI 架构 | `+page.svelte` 组合邮箱状态，`mail/`、`shell/`、`ui/` 已分层；SvelteKit 路由和服务端 API 分离；域名与地址有独立导航视图 | `+page.svelte` 仍同时处理列表、详情、草稿、搜索、标签、批量操作和布局，状态依赖密集 |
| 组件复用 | Button、IconButton、Dialog、Drawer、DropdownMenu、表单、状态、空态和骨架屏均有共享组件 | 写信的地址 chip、附件操作和管理页部分按钮仍手写样式；相同状态的 hover、focus 与触控尺寸容易漂移 |
| UX | 支持多发件身份、草稿自动保存、批量选择、搜索、专注阅读和安全 HTML 展示；跨文件夹星标与持久化标签已有独立服务端视图，当前页所选邮件可批量添加/移除标签，非草稿选中项可跨文件夹执行适用的状态操作 | 草稿和普通邮件混选时仅能批量管理标签；大规模邮箱与浏览器兼容性仍需独立验收 |
| 布局 | 桌面三栏、侧栏折叠、可调整列表宽度和移动端单面板都已存在；域名与地址已从设置页分离 | 设置页资料、通知和诊断仍是连续长表单，已增加分区跳转和固定保存入口；小屏下写信的高级 HTML 区和附件区会显著拉长滚动距离 |
| 可维护性 | `DESIGN.md` 已定义颜色、字号、间距、主题、响应式和可访问性约束 | 新功能需要继续拆分 `+page.svelte` 的领域状态；设计规范与实际新增交互需同步，避免文档宣布功能而代码尚未实现 |

## 分阶段工作

1. 写信主流程：最近联系人补全；让高级 HTML 默认收起，并把附件和 HTML 选项放在固定操作区；桌面浮动窗口支持拖动、缩放、最小化和最大化，同时保留键盘焦点与草稿安全。
2. 导航与身份管理：明确区分文件夹、全局星标、标签、域名、地址和设置。跨文件夹视图需要服务端分页与计数，不能把当前页筛选伪装成全局结果。
3. 阅读与列表：逐项核对长正文、长主题、大附件、多域名/多地址和批量操作；邮件多时再按测量结果考虑虚拟列表。
4. 完整验收：1920、1440、1366、768、390 px；浅色与深色；Chromium、WebKit、Firefox；键盘、焦点、可访问名称、对比度和屏幕阅读器。Linux WebKit 模拟不等同于真实 Safari。

第 1 阶段已落地联系人补全、写信操作区整理和桌面浮动窗口。建议来源限于当前浏览器会话已加载的收件/已发送邮件，去重后排除用户自己的受管地址；它不是全量通讯录，也不把联系人写入本地存储。其余事项仍须按上述范围实现和验证。

导航与管理进展：域名概览、邮箱地址管理和设置已拆成三个可直达的导航状态；域名卡片已增加收信/发信能力汇总，按现有路由、地址状态和发送门禁保守判断，检查证据过期时提示复核而非宣称真实投递。地址创建仍复用原有受管身份 API，未把域名配置或供应商状态检查改成自动写操作。全局星标已新增独立的 Owner 范围服务端分页、计数、搜索和地址筛选，收件、归档、已发送与草稿均在范围内。标签现可创建、重命名、删除和应用到邮件，D1 `0027` 保存 Owner 标签及邮件关联；标签视图按服务端跨文件夹分页。邮件详情中的新建标签会直接应用于当前邮件；标签工具栏和表单复用共享控件。标签批量操作现可在收件、已发送、归档、星标和标签视图针对当前页明确勾选的邮件添加/移除标签，服务端先验证每封邮件的 Owner 与未删除状态，再在一个 D1 batch 中提交；草稿和入站邮件分别按自身类型校验。星标/标签视图还可对明确选中的非草稿邮件跨收件、归档和已发送执行已读/未读、星标/取消星标与移入垃圾箱；全为收件时可归档或移回收件箱。服务端重新校验 Owner、地址范围以及星标或标签成员关系，不扩展会话；含草稿的选择会明确提示只支持批量标签，避免静默跳过。以上仅有本地 D1/浏览器证据，不代表远程 D1 已迁移或生产已发布。

混合视图批量操作验收：隔离本地 D1 的 Bun 测试覆盖跨收件、已发送和入站的选中邮件、标签成员与地址过滤、草稿拒绝及失败时不部分写入；路由测试覆盖标签范围缺失与跨文件夹扩大到整段会话的拒绝。Chromium 桌面/390 px 手机经标签视图验证草稿选择限制、收件与已发送的已读和移入垃圾箱、刷新后的状态及单条成功提示；WebKit 桌面/iPhone 验证收件、已发送、草稿混合标签视图的选择与移除；Firefox 桌面验证全局星标视图中收件和已发送邮件的已读、取消星标。截图位于 `/tmp/flaremail-mixed-bulk-{draft,selected}-{desktop,mobile}.png` 与 `/tmp/flaremail-webkit-mixed-bulk-{webkit-desktop,webkit-iphone}.png`。这些是本地 Worker 和浏览器引擎证据，不代表真实 Safari、生产邮件或远程 D1 验收。

批量选择的客户端派生状态现使用共享 ID 集合与线性去重投影，列表逐行选中标记也直接查询集合；不再在每个选中状态变化时对可见行反复做嵌套数组查找。Bun 测试覆盖线程与普通行重叠、页外选中项不进入操作，以及 5,000 行的顺序保持。隔离本地 Chromium 桌面验证了加载下一页后已选状态仍在、文件夹切换与退出登录时清空；390 px 手机验证了标签视图中的混合选择、操作及草稿保护。1505×1045 工作台截图 `/tmp/flaremail-list-default-desktop.png` 与手机选择截图 `/tmp/flaremail-mixed-bulk-selected-mobile.png` 已复看。这是算法复杂度、正确性与局部浏览器回归证据，并非已取得真实大邮箱性能 trace。

普通邮件列表现显示第一枚用户标签，更多标签以数量提示，且完整标签名称进入邮件按钮的可访问名称；标签筛选页已有当前标签标题，列表内不重复显示标签徽标。隔离本地 Chromium 桌面与 390 px 手机验证了打标签后列表即时更新、读屏名称、标签视图去重及无横向溢出；截图位于 `/tmp/flaremail-label-chip-{desktop,mobile}.png`。

搜索补齐持久化标签语义：`label:"标签名"` 现在同时匹配旧邮件元数据标签与 Owner 范围的新用户标签；关键词、发件人或主题等条件仍可与它组合，重命名及移除标签后结果立即反映当前关系数据，不另建易过期的索引。隔离本地 D1 集成测试覆盖收件、入站、已发送、草稿、旧标签及组合条件；Chromium 桌面和 390 px 手机验证了搜索、刷新持久性与清除搜索，截图位于 `/tmp/flaremail-label-search-{desktop,mobile}.png`。这不是生产 D1 或大规模邮箱性能证据。

WebKit 搜索截图发现原生清除装饰与应用清除按钮重叠出现两个“×”，桌面端快捷键提示还会遮住清除按钮；搜索输入现使用具备 `searchbox` 语义与搜索键盘提示的文本控件，保留共享图标按钮作为唯一清除入口，仅空查询时显示快捷键提示。隔离本地 WebKit 桌面/iPhone 的搜索与批量标签路径已复核，截图为 `/tmp/flaremail-label-search-{webkit-desktop,webkit-iphone}.png`；Linux WebKit 证据不等同于真实 Safari。

搜索焦点复核：隔离本地 Chromium 桌面曾复现清除查询后输入框变为 inactive；现在清除按钮在同一用户手势内将焦点交给输入框，可立即重新键入，鼠标点击与 Enter 激活均已回归。390 px 手机的搜索输入在邮箱请求加载期间不再被禁用，测试等待带 `q=E2E` 的本地 API 响应后仍确认焦点留在输入框，清除后同样恢复焦点。Firefox 桌面覆盖点击与 Enter 两种清除方式，Linux WebKit iPhone 模拟确认清除后焦点返回；截图为 `/tmp/flaremail-search-clear-{desktop,mobile,firefox,webkit-iphone}.png`。Browser plugin 当前不可用，使用 Playwright fallback；该自动焦点断言不能替代真实屏幕阅读器与 iOS 软键盘检查。

完整 Chromium 串行验收曾暴露两个缺口：批量移入垃圾箱用例未恢复随后仍要使用的两封固定 fixture，现完成断言后精确恢复它们；搜索清除与筛选切换之间偶发失去点击，定向挂起邮箱请求复现了筛选按钮在加载时被禁用。现在筛选和身份选择在邮箱加载期间保持可操作，客户端只采用最新请求的结果；桌面与 390 px 手机都验证了请求挂起时连续切换筛选和域名身份，释放旧请求后 URL 与控件仍反映最后选择。截图为 `/tmp/flaremail-filter-during-refresh-{desktop,mobile}.png`。此处是隔离本地 Chromium 证据，尚不代表真实大邮箱延迟或 Safari 软键盘行为。

最终截图复核还发现桌面阅读区空态出现两个相同图标：共享 `EmptyState` 已提供默认图标，邮件详情不应再插入第二个。现在 1505×1045 桌面回归断言空态只有一个 SVG，截图为 `/tmp/flaremail-empty-detail-single-icon-desktop.png`。本轮完整本地套件：Chromium 桌面/390 px/320 px 分别通过 46/35/28 项，Firefox 桌面通过 14 项，Linux WebKit 桌面/iPhone/iPad 分别通过 13/12/10 项；各项目另有按视口条件跳过的用例。空态单图标与加载中筛选的最终代码另跑了 Chromium 桌面定向用例。Linux WebKit 不能替代真实 Safari 或 iOS 设备，浏览器自动化也不能替代手动屏幕阅读器验收。

跨页面无障碍复核：隔离本地 Chromium 在 1505×1045 桌面和 390×844 手机各走完收件箱、邮件详情、写信、设置、域名、邮件地址六个主要状态，浅色与深色各扫描一次 WCAG 2.1 AA 自动规则并检查页面级横向溢出。首次在写信状态复现通知容器的无效 `aria-label`；现移除普通容器上的名称，保留其 `aria-live` 与每条通知自身的 `status`/`alert` 语义，重跑两个视口均通过。桌面截图为 `/tmp/flaremail-journey-inbox-{light,dark}-desktop.png`；手机阅读与写信截图为 `/tmp/flaremail-journey-{detail,compose}-{light,dark}-mobile.png`。这证明自动规则覆盖到上述状态，不等于真实屏幕阅读器播报、实际 Safari 或整站所有动态状态验收。

批量标签验收：Bun 集成测试覆盖四类来源的事务写入、重复目标去重、其他 Owner 与已删除邮件拒绝、超出 100 条限制及无部分增删；隔离本地 Chromium 桌面/390 px 手机经 UI 全选、逐封勾选、添加新标签、移除其中两封并刷新复核。弹窗在 390/320 px 均不越过视口，320 px 操作改为逐行全宽；Escape 关闭后将焦点还给发起按钮，浅色/深色弹窗通过 axe WCAG 2.1 AA 自动扫描。隔离本地 WebKit 桌面/iPhone 验证收件与草稿混合选择的批量移除，Firefox 桌面验证收件与已发送混合选择的批量添加及刷新后持久性；这些浏览器引擎测试不等于真实 Safari 设备测试。截图位于 `/tmp/flaremail-labels-bulk-{desktop,mobile}.png`、`/tmp/flaremail-labels-bulk-dialog-{desktop,mobile}.png`、`/tmp/flaremail-labels-bulk-dialog-narrow.png`、`/tmp/flaremail-webkit-bulk-label-{webkit-desktop,webkit-iphone}.png` 和 `/tmp/flaremail-firefox-bulk-label-dialog.png`。这不等于真实屏幕阅读器或生产 D1 验证。

设置页资料草稿现在按字段保留未保存编辑：其他标签页的身份变更触发会话刷新时，只同步未编辑字段；保存成功后显示服务端规范化结果。隔离本地 D1 的双标签页 Chromium 桌面与移动端回归均已覆盖这一行为。

设置长表单现有资料、通知、外观、诊断和 Telegram 分区链接；使用原生锚点，键盘可进入，滚动时导航与保存栏保持可见，跳转不卸载未保存字段。移动端改为工作区内部滚动并约束容器宽度，避免导航把页面撑宽，也让全局顶栏留在视口中。临时通知在设置页上移，不覆盖保存栏。隔离本地 Chromium desktop/mobile 已验证跳转位置、草稿保留、键盘激活、深色主题、无横向溢出和 axe 主区域扫描；截图位于 `/tmp/flaremail-settings-sections-{desktop,mobile}.png` 与 `/tmp/flaremail-settings-appearance-dark-{desktop,mobile}.png`。这些不是完整屏幕阅读器或真实设备证据。

设置页分区交互还通过了隔离本地 WebKit desktop/iPhone/iPad 与 Firefox 的回归：锚点跳转后标题不被导航遮住、保存入口留在视口、未保存姓名保持不变；Firefox 覆盖 1920/1440/1366/768/390 px。截图位于 `/tmp/flaremail-settings-webkit-{webkit-desktop,webkit-iphone,webkit-ipad}.png` 和 `/tmp/flaremail-settings-firefox-{1366,390}.png`。Firefox 首次运行因测试容器禁止 user namespace 且 XDG/dconf 目录只读，在浏览器启动阶段超时；将 XDG 缓存、配置和运行目录指向 `/tmp` 并为该容器禁用 Firefox 内容沙箱后重跑通过。这些仍是 Linux Playwright 模拟结果，不等同于真实 Safari、实体设备或屏幕阅读器验收。

图标操作进展：共享 `IconButton` 已接入可悬停、可键盘聚焦的 Tooltip，保留直接作用于按钮的 accessible name，并用稳定的服务端/客户端 ID 关联提示。浏览器截图曾发现顶部提示被顶栏遮挡、中文被压成竖排、移动端返回提示超出视口；现按工具栏/列表/写信底栏及视口边缘设置方向与内容宽度，并用端到端几何断言防止回归。顶栏搜索宽度规则也已收窄到搜索组件根节点，避免影响清除按钮。

折叠侧栏的图标导航、写信、标签和管理按钮现复用共享 Tooltip，不再只依赖浏览器原生 `title`。可滚动标签区的提示以视口为坐标定位，滚动时跟随仍可见的触发器或关闭已滚出区域的提示，避免标签名称被侧栏裁切；展开侧栏已有可见文字时不重复显示提示。视口监听器只在提示实际显示时注册，避免标签多时为每个隐藏提示保留监听。隔离本地 Chromium 桌面验证了鼠标悬停、键盘焦点、Escape、提示与触发按钮的 `aria-describedby`、19 个标签引发滚动后的显示和关闭、提示越过侧栏边界、未读角标位置、浅色/深色、无横向溢出及侧栏 axe WCAG 2.1 AA 自动规则；WebKit 与 Firefox 桌面分别验证了标签滚动区外的提示可见。截图位于 `/tmp/flaremail-sidebar-tooltip-desktop.png` 与 `/tmp/flaremail-sidebar-tooltip-desktop-dark.png`；这仍不等于真实 Safari 设备或屏幕阅读器验收。

写信的 To/Cc/Bcc 收件人 chip 已归入同一邮件组件，移除操作统一使用带 Tooltip 的 `IconButton`，保留字段和邮箱的无障碍名称及手机 44 px 触控目标。共享 Tooltip 现在只允许一个提示处于待显示或显示状态，避免指针留在写信窗口关闭图标时再用键盘聚焦移除图标出现双提示。隔离本地 Chromium 桌面/手机的写信与图标引导回归、WebKit iPhone 的 To/Cc/Bcc 草稿及附件 smoke 均通过；手机视觉截图位于 `/tmp/flaremail-compose-recipient-tooltip-mobile.png`。这些不代表真实 Safari 或完整屏幕阅读器验收。

写信窗口进展：桌面使用不锁定工作区的浮动写信窗口，可拖动、键盘调整位置和尺寸、最小化与最大化；手机保持全屏。草稿与附件状态属于写信组件，不因最小化销毁。隔离本地 Chromium 曾在 1366×320 px 复现窗口底边达到 368 px、发送底栏离开视口；现让桌面最小高度在可用视口不足时让位，1366×320 与刚超过手机断点的 641×320 px 均确认标题、可滚动正文和底栏位于视口内，且无页面级横向溢出。Chromium 还验证了键盘调整、最大化/还原后仍在视口内及关闭后焦点回到写信入口；Firefox 与 Linux WebKit 桌面分别确认 1366×320 px 的窗口和底栏几何。截图为 `/tmp/flaremail-compose-floating-{1366x320,641x320}.png`、`/tmp/flaremail-compose-floating-short-{firefox,webkit}.png`。1505×1045 px 的新截图 `/tmp/flaremail-compose-floating-concept-size.png` 对照已接受的桌面概念稿：三栏结构、白色内容面、蓝色主操作、淡蓝选中行和橙色品牌延续；浮窗、合成测试邮件和更密集的顶栏/邮件行是功能或现有设计差异，并非概念稿原状态。Browser plugin 当前不可用，以上为 Playwright fallback；真实软键盘、更多焦点序列、真实 Safari 和屏幕阅读器仍待验收。

手机写信概念稿 `docs/design-concepts/flaremail-mobile-compose.png` 与最新 390 px 截图已并排检查：白色表面、蓝色主操作、地址 chip、正文留白和底部固定操作区保持同一视觉语言；标题位置、收件人行密度、抄送/密送入口、保存状态和底部按钮排列仍有明显差异。当前额外的发件身份选择是多域名发送所需，不应为贴图移除；其余差异属于后续手机写信布局优化范围，本轮 chip/Tooltip 修复不构成概念稿的完整视觉验收。

手机写信布局已随后按概念稿收敛，并以 390×844 px 的隔离本地 Chromium 截图 `/tmp/flaremail-compose-layout-mobile.png` 回看：标题居中、左侧关闭、简短保存状态、收件人 chip、抄送/密送分隔行、主题行、开放正文及底部三按钮都已接近参考；正文内容和空白长度取决于测试草稿。差异仍有：标题保留“新邮件/回复/转发”等真实模式而非固定“写邮件”；多域名必需的发件地址行保留且长地址会截断；右上角未添加无对应功能的省略号；高级 HTML 与附件管理仍在正文之后，底栏提供快捷入口。收件人地址过长或有多个地址时允许换行，不能为了视觉稿裁掉真实收件人。320×720 px 的本地 Chromium 草稿回归亦通过，截图 `/tmp/flaremail-compose-layout-narrow.png` 显示底部按钮均在视口内，页面无横向溢出。隔离本地 WebKit iPhone 的 To/Cc/Bcc、附件上传、草稿恢复 smoke 通过；这些仍不等于真实 Safari 或屏幕阅读器验收。

后续首屏复查发现收起的高级 HTML 区仍露在 390 px 正文下方；已调高手机正文最小高度，让高级区和附件区留在滚动内容中。底栏 HTML 图标展开选项后会把标题滚入写信窗口；隔离本地 Chromium 手机测试对标题可见几何与草稿恢复再次通过。长正文、多个附件和软键盘弹出时的真实设备滚动仍待专项验收。

短视口写信复核：隔离本地 Chromium 在 390×500 px 下填入 100 行正文并上传两份 128 KB 附件，确认内容区独立滚动、两份附件的命名和操作保持单行、标题与底栏不离开视口、草稿能保存并回到详情，且含附件状态的写信窗口通过 axe WCAG 2.1 AA 自动规则。附件重试/删除图标改用共享 `IconButton`，名称与操作成组响应宽度，删除按钮保持危险操作色；320 px 下操作另起一行但不孤立。隔离本地 WebKit iPhone 同样在 390×500 px、100 行正文和两份 128 KB 附件下确认两张附件卡片确实进入标题与底栏之间的可视区、操作仍在卡片内，并能保存草稿。打开写信时会撤去旧的普通成功/信息提示，以免覆盖附件操作，保留持久、带操作和警告/错误提示。对照手机概念稿，居中标题、关闭入口、白色表面、蓝色主操作及三按钮底栏延续同一语言；当前截图滚动到附件区，概念稿没有同等附件内容，保存状态又随测试时序变化，不能据此判定首屏完全一致。截图为 `/tmp/flaremail-compose-short-{mobile,narrow}.png` 和 `/tmp/flaremail-compose-short-webkit-iphone.png`。500 px 视口只是软键盘遮挡的近似场景，不是实体键盘、真实 iOS Safari 或屏幕阅读器证据。

短视口深色复核：同一份长正文与两份附件的草稿在刷新后以深色主题重新打开，正文末行与附件均保留；390×500 px 截图 `/tmp/flaremail-compose-short-mobile-dark.png` 显示两张附件卡片、危险操作色与固定底栏，axe WCAG 2.1 AA 自动规则无违规。复查发现“继续编辑草稿”信息提示会在打开窗口后压住第二张附件卡片；现不再为草稿、回复、回复全部与转发重复弹出模式提示，改由写信标题和内联保存状态提供上下文。错误及可撤销通知不受影响。这是隔离本地 Chromium 的视觉与自动规则证据，非真实设备或人工无障碍验收。

浏览器验收进展：Firefox 桌面隔离 D1/R2 smoke 的 7 项已通过，覆盖收件阅读、邮件标签持久化、第二发件身份写信，以及域名页在 1920/1440/1366/768/390 px 的浅色和深色布局。WebKit 桌面、iPhone、iPad 的七项 smoke 均已各自连续通过，涵盖导航/搜索/阅读、安全 HTML、写信/草稿/假发送、主题及交互语义。这些是 Linux Playwright 模拟证据，不等于真实 Safari 或生产邮件验证。完整屏幕阅读器、极端内容和真实设备验收仍待完成。

极端内容进展：Firefox 隔离 smoke 已覆盖约 450 字符的超长主题、400 行正文，以及手机宽度上传、模拟发送和下载 7 MB 附件的完整路径；1366/768/390 px 无页面级横向滚动。写信底栏现在显示已就绪附件数量，附件大小按 B/KB/MB 展示，长主题展开控件文字更清晰。仍需在其他浏览器、真实设备以及更多特殊邮件内容上复核，不能将这组 smoke 视为全部极端场景验收。

附件计数复核：手机写信底栏与桌面浮动窗口分别使用可见的计数徽标和稳定的屏幕阅读器状态区域。Firefox 390 px 的 7 MB 本地附件流程现在断言手机徽标确实可见、附件按钮关联正确的状态说明，并扫描含附件写信窗口的 WCAG 2.1 AA 自动规则；不再把隐藏的桌面徽标当作手机证据。真实屏幕阅读器播报仍须设备实测。

视觉比对进展：以 1505×1045 的本地 Chromium 截图对照 `docs/design-concepts/flaremail-desktop-workspace.png`。三栏结构、白色内容面、蓝色写信入口、淡蓝选中态和橙色品牌色保持一致。概念稿的侧栏/列表约为 240/447 px，当前为 232/440 px；顶栏从 50 px 增至 64 px，仍比概念稿约 74 px 更紧凑；桌面邮件行从约 76 px 增至 88 px，仍比概念稿约 98 px 更密集。顶栏搜索现居中且有最大宽度，右侧账号改为仅头像入口，保留可访问名称和菜单。合成测试邮件的内容、额外导航项和详情中安全 HTML 控件与概念稿不同；真实 Safari、屏幕阅读器及完整视觉忠实度仍未获证实。
