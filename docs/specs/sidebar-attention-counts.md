# 侧栏关注计数 Spec

状态：已实现；本轮验证仅使用隔离本地 Worker、D1/R2 和合成数据。

## 核实与目标

此前桌面 Inbox 显示未读数，星标、草稿、已发送和垃圾箱显示各自总数，归档不显示数字；手机缺少发送数字，部分计数未统一截断。总数提示邮件规模，容易掩盖用户真正需要关注的事项。

目标是让数字只表示待关注或待处理邮件，不改变分类入口和列表总数，不因搜索、分页或收件分类改变提醒范围。

## 展示契约

| 分类 | 数字含义 |
| --- | --- |
| Inbox | 所选 Owner/域名/地址范围内未删除、未归档收件的未读数 |
| 草稿 | 同一身份范围内全部未删除草稿，每份草稿均属于未完成事项 |
| 已发送 | 同一身份范围内发送中、延迟、失败/抑制、退信、投诉的未删除邮件数 |
| 星标、归档、垃圾箱、标签、管理入口 | 不显示数字，用户可进入分类查看列表 |

桌面侧栏、折叠侧栏、手机导航共用规则。零值或当前身份统计尚未到达时不显示徽标；1–99 显示实际值，超过 99 显示 `99+`。完整数量及“未读/邮件/发送中或需处理”含义保留在 title、可访问描述和折叠侧栏 Tooltip 中，保持导航按钮名称稳定。

发送提醒 = `queuedCount + delayedCount + failedCount + bouncedCount + complainedCount`。

- queued/submitting 属于发送中；delayed 属于等待重试；failed/suppressed、bounced、complained 属于异常。
- `staleDeliveryCount` 是 submitting 的子集，不再相加。
- sent/delivered 的正常邮件不计入；计数单位是邮件，不是会话、尝试次数或 webhook 事件数。
- 统计只连接当前 Owner 的现存、未删除 sent 邮件，排除已进垃圾箱、无对应邮件或错误关联其他文件夹的状态记录。
- 发送列表仍显示全部发送邮件，其总数不随徽标语义改变。本轮不新增提醒筛选或自动重试。

## 范围、更新与兼容

保持现有身份范围统计 API 和缓存机制；切换身份时所有提醒数字均检查响应身份，不展示旧范围的数据。状态操作更新或失效统计缓存，并移除邮件视图缓存内的旧 metrics，避免返回缓存文件夹时覆盖新提醒数；删除、恢复、永久删除、清空垃圾箱和保存资料返回的 Owner 统计只接受到相同身份范围，存在域名/地址筛选时重新读取对应范围，避免污染草稿和发送提醒。垃圾箱的手动/跨标签页刷新同时刷新所选身份统计。

既有 API 的文件夹总数、列表标题和投递状态字段保留语义，投递计数收紧为有效未删除发送邮件。无需依赖、schema、迁移或绑定变更；统计仍使用每个来源的条件聚合，不增加每封邮件查询。
