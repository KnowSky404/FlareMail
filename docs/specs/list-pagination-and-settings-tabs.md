## 目标与覆盖范围

所有独立数据列表提供上一页、下一页和当前页，设置页只展示选中标签的功能，并删除设置标题旁的重复语言入口。

| 数据列表 | 页面范围 | 默认页大小 | 数据来源 |
| --- | --- | --- | --- |
| 邮件 | 收件箱及分类、已发送、草稿、归档、星标、标签、搜索结果 | 40 封记录 | 现有服务端游标 |
| 域名 | Domains 管理 | 10 条，可选 20/50/100 | 完整配置集合，筛选和排序后客户端分页 |
| 邮箱地址 | Email addresses 管理，含域名和生命周期筛选 | 10 条，可选 20/50/100 | 完整配置集合，筛选和排序后客户端分页 |
| 回收站 | 工作区邮件、草稿、入站邮件的统一回收站 | 40 条 | 扩展服务端游标 |
| Telegram 历史 | Telegram 标签中的投递记录 | 20 条 | 扩展历史查询接口 |

附件、会话内邮件、邮件投递时间线、侧栏导航及下拉候选项沿用现有展示。邮件按记录分页，同一会话可跨页出现；合并后的会话行数可以小于每页记录上限。页大小选择器用于域名和邮箱地址表格；不增加任意跳页。

## 分页行为与接口

### 通用控件和状态

- 复用一个分页控件，接收当前页、是否有上一页/下一页、加载状态、可选准确总数/总页数，以及翻页回调。分页与各数据控制器分离。
- 完成首次读取后，空列表、单页和多页均显示分页区。第一页禁用上一页，末页禁用下一页；空态显示零条结果，两个方向均禁用，不显示“第 1 / 0 页”。
- 有准确总数时显示“第 N / M 页”；没有时显示“第 N 页”。总数与当前搜索、筛选和分页单位一致，不能使用全局徽标或会话行数替代邮件记录总数。
- 翻页展示目标页内容，保持搜索、分类、身份和排序。查询条件变化回到第一页并重置游标历史；显式刷新从第一页重建服务端页链。资源刷新保留筛选并将页码收敛到有效范围。
- 上一页使用对应页的缓存或已记录的请求游标。首次无缓存才显示骨架；缓存过期可先显示旧页再校验，沿用现有 30 秒新鲜期和最多 16 个邮件视图的会话内存缓存边界。
- 列表页码及游标只保存在当前认证会话内存，整页刷新从第一页开始；邮件阅读返回仍恢复当前列表上下文。
- 翻页请求期间阻止重复翻页。失败保留原页内容和页码，显示错误并允许重试。取消旧请求并检查响应代次，迟到响应不能覆盖新的查询、页或认证会话。
- 成功翻页后列表滚动到顶部；上一页恢复该页已有滚动位置。分页区有可访问名称、明确的加载/页码反馈和适合触控的按钮，320 px 下不造成页面横向溢出。

### 邮件和资源列表

邮件继续使用 `GET /api/workspace/mailbox` 和现有 `MailboxPage` 响应；不增加邮件总数查询或任意跳页接口。页级缓存保存原始记录页及游标，不再把下一页追加到当前渲染集合；分类、搜索、状态、身份、标签和 limit 共同决定分页上下文。

列表聚合仅以当前记录页为基础，不借用其他页记录填满会话行。翻页清空当前页的批量选择并恢复默认范围。全选、默认批量操作和键盘列表选择只针对当前页；保留用户主动选择的“当前筛选内的会话邮件”和“整个 Owner 会话”扩展选项，按原有服务端范围契约处理。翻页不自动打开首封邮件。合法邮件深链仍可加载详情，不能为了显示目标而将其插入当前列表、突破分页上限。

保留已有状态修补、认证隔离和缓存失效规则。已读/星标变化不扩展到其他邮件或会话；不再匹配筛选的记录从对应缓存页移除。归档、删除、恢复等成员变化后使相关服务端页链失效并从第一页重新读取，避免停留在空末页；资源列表继续将页码收敛到最后一个有效页。

域名和地址复用 `filterMailDomains`、`filterMailAddresses`、`paginateMailResources`。完整配置继续用于关联计数、发件选项和能力判断；切片只用于当前表格展示。保留现有资源编辑、删除预检、恢复、Retry、显式同步、焦点恢复和未知写入结果处理。

域名和地址默认每页 10 条，可选择 10、20、50、100。调整大小时回到第一页，保留搜索、筛选和排序；滚动恢复以页大小区分上下文，浏览器重新加载后恢复默认值。页大小选项与共用分页控件在空结果或单页时均保持可用。

### 回收站与 Telegram 的新增分页契约

| 接口/类型 | 目标变化 | 兼容要求 |
| --- | --- | --- |
| `GET /api/workspace/trash?limit=…&cursor=…` | 接收可选不透明 cursor；响应新增 `nextCursor: string \| null`，继续返回 `items`、`hasMore`、`metrics` | 无 cursor 时读取第一页；保留默认 limit 100 和合法范围 1–500，浏览器显式请求 40 |
| `TrashListResult` | 增加 `nextCursor`，供页级控制器记录后续位置 | 更新全部客户端及 fixture；已有字段语义保持一致 |
| `GET /api/workspace/notifications/telegram/deliveries?limit=…&cursor=…` | 响应增加 `nextCursor`、`hasMore`，保留 `deliveries` | 无 cursor 时读取第一页；保留默认 limit 20 和合法范围 1–50 |
| Telegram 历史客户端 | 增加独立的带游标查询与页级状态 | 设置状态与历史分页分别更新；保留 `recentDeliveries` 的原有响应兼容性，列表不再依赖其十条截断 |

回收站按 `deletedAt DESC`、公开 ID DESC、`kind DESC` 排序；入站 `email:` 前缀参与公开 ID 比较。三种来源均应用统一游标边界，以一致的字符串比较顺序合并，再截取 limit 条并用多取一条判断 `hasMore`。游标应表达稳定位置，不依赖边界记录仍存在。

Telegram 按现有 `createdAt DESC, id DESC` 顺序分页，多取一条判断后续页。两个接口的游标都限定查询类型和当前 Owner；非法、错类型或跨 Owner 的游标返回 `400 INVALID_CURSOR`，非法 limit 沿用 `400 INVALID_LIMIT`。无后续页时 `nextCursor` 为 null；cursor 不替代每次请求的认证和所有权过滤。

展示分页不改变回收站清空、永久删除及 R2 清理的写入范围和保护；也不改变 Telegram 重试条件及 unknown delivery 的人工重复风险说明。读取下一页不能触发重试、绑定、测试通知或其他写入。

## 设置标签、保存和语言入口

### 分组与导航

| 标签值 | 名称 | 功能与保存方式 |
| --- | --- | --- |
| `profile` | 个人资料 | 姓名、角色、公司、时区、位置、显示邮箱、签名；保留自动回复说明。显式保存当前标签 |
| `notifications` | 通知 | 入站通知开关及运行配置说明。显式保存当前标签 |
| `diagnostics` | 诊断 | 运行/绑定状态、投递指标；域名和邮箱管理快捷入口 |
| `telegram` | Telegram | 运行配置、绑定、通知选项、测试、分页历史和人工重试；使用各自现有操作 |

默认进入个人资料，只有当前面板参与可见布局、可访问树和焦点导航。使用 `tablist`、`tab`、`tabpanel`、`aria-selected`、`aria-controls` 和 `aria-labelledby`；标签采用单个 Tab 停靠点，左右方向键及 Home/End 移动焦点，Enter/Space 激活。窄屏可横向滚动标签条，当前焦点标签始终可见。

URL 使用 `folder=settings&tab=<值>`，保留 `view=domains|addresses` 与 `domain` 的既有管理语义。个人资料的默认 URL 可省略 tab；缺失或非法 tab 回到个人资料。标签激活记录历史，刷新及前进/后退恢复标签；离开设置或进入资源管理时清除 tab 和设置锚点。

兼容 `#settings-profile`、`#settings-notifications`、`#settings-diagnostics`、`#settings-telegram`：没有合法 tab 时映射旧锚点到对应标签，使用 replace 规范化 URL；合法 tab 优先。标签切换不再执行页面分区锚点跳转。设置页已移除重复的外观标签和主题选择器，桌面通过全局显示偏好、手机通过全局导航抽屉切换主题，继续即时生效并持久化；浏览器禁止主题存储时，当前标签页的选择器仍与已应用主题同步。旧 `tab=appearance` 和 `#settings-appearance` 链接按无效标签回到个人资料并规范化 URL。

移除外观标签后的[桌面](../images/settings-without-appearance-desktop.png)和[手机](../images/settings-without-appearance-mobile.png)截图来自隔离本地 synthetic 数据，示例邮箱字段已遮挡；不代表远程 Owner 验收。

### 草稿和独立保存

个人资料和通知的草稿由设置容器持有，生命周期覆盖整个设置页。切换标签不清空输入、不自动保存；后台资料刷新按字段合并未编辑值。此约定不新增跨刷新或离开设置后的草稿持久化。

个人资料保存字段为 `name`、`role`、`company`、`timezone`、`location`、`email`、`signature`；通知只保存 `forwardingEnabled`。继续调用 `PUT /api/workspace/profile`：以最新已确认的服务端资料为基底，仅覆盖当前标签草稿字段，其他标签使用服务端值，避免提交其未保存或无效输入。

保存成功只确认提交标签的字段并吸收服务端规范化结果，另一标签的草稿继续按字段合并保留。个人资料和通知共用一个保存锁：任一资料 PUT 未结束时，两者均禁用编辑和保存，仍允许切换标签查看，不能从另一标签并发提交。保存锁释放后，下一次提交必须以最新已确认的服务端响应为基底，避免完整资料写入覆盖前一次保存。保存失败保留输入，反馈归属提交标签。非当前标签的必填字段不参与当前表单校验。诊断和 Telegram 不显示资料保存按钮。

Telegram 第一次激活才读取状态及历史；离开标签后保留组件实例和绑定链接、候选状态、反馈。组件需要可感知当前是否激活：隐藏时取消状态/历史读取及绑定轮询，暂停窗口 focus 引起的读取，阻止异步结果将焦点或滚动移入隐藏面板；正在进行的显式写入按原结果处理，不能自动重复。重新激活时核对链接有效期并读取最新状态，认证会话结束时清理临时状态。

### 语言入口

删除设置页 header 内的 `LanguageSwitcher` 及其专用引用。桌面继续从全局 Display preferences 切换语言，手机继续使用导航抽屉中的语言入口；登录页原有入口保留。标签、分页、错误及可访问名称随全局语言更新，不重置当前分页、标签或草稿。
