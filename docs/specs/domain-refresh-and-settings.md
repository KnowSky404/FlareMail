# 域名批量刷新、自动检查与设置体验

状态：2026-11-13 已确认方案，按本 SPEC 实施。

## 问题与目标

Cloudflare catch-all 的修改不会立即更新 FlareMail 保存的检查结果。现有
“刷新列表”只读取 D1，页面定时器只更新时间显示，用户可能仍被旧结果阻止启用
Collect。域名设置还把固定映射、日常说明和实际警告混在一起；部分错误直接
显示后端中文 message，绕过英文界面的翻译。

目标是让用户明确发起全面检查、及时看到最新状态、安静地编辑设置，并获得
当前界面语言下的具体错误建议。

## 域名页与批量操作

- 在 Add domain 左侧放次级按钮 **刷新全部 / Refresh all**。
- 移除域名页原有的刷新图标；“更多操作”保留仅重读保存状态的“刷新列表”，
  用于检查后读回失败等恢复场景。地址页保留原来的刷新按钮。
- 刷新全部覆盖操作开始时已加载的所有接入域名，不受搜索、筛选和分页影响。
  复用单域名检查接口，最多同时检查两个域名。
- 显示完成数量与总数量，执行中阻止重复点击；单个失败不影响其他域名。
  完成后报告总数、需处理数量，并标记对应行，保留单域名检查与诊断入口。
- 不能仅依据 HTTP 200 判断成功；还要检查 Cloudflare/Resend 返回状态和错误码。
  未配置 Resend 不算检查失败；无效响应按单个域名失败处理。地址规则的冲突、
  缺失、待导入等也计入需处理数量。最终读回按供应商观察时间和错误元数据
  保留本轮批量检查快照，不能丢失尚未持久化的地址观察结果。
- 不发现或导入新域名，不修改供应商规则，不改变用户的收信、发信偏好。

## 自动刷新

- 域名页可见、在线、空闲且认证有效时，每 60 秒重读保存状态。
  进入页面、返回标签页和恢复网络时也检查是否需要更新。
- 某供应商上次成功或失败的检查已满五分钟时，自动复查该域名的供应商健康。
  关闭页面后沿用原有后台调度，不改成全站高频扫描。
- 自动复查复用已有健康观察逻辑，只更新健康记录；不调用完整的地址状态协调
  路径，不改变地址生命周期、所有权或用户偏好。
- 使用需要认证的单域名 POST，按当前 Owner 限定域名。复用后台每供应商独立锁，
  在 D1 原子获取锁时同时检查成功时间与错误时间，实施五分钟冷却。
  多标签页、后台任务共享锁；客户端参数不能绕过冷却。
- 弹窗、编辑、手动操作或检查期间暂停；隐藏、离线、登录失效时暂停。
  卸载或登录失效后停止排队请求，丢弃迟到结果，不自动重放被打断的写入。
- 自动更新不清空列表、不重置筛选、不抢焦点、不弹成功通知；失败时保留已有
  数据。静默读取不能取消正在进行的手动读取或遗留 loading 状态。
  成功时间未变化但错误码/错误时间变化时，必须丢弃旧诊断缓存。
  客户端最多同时处理两个域名，各供应商错误互不影响。

## 域名编辑弹窗

- 主要内容保留域名身份、启用状态和未知地址处理方式。
- Zone ID、Worker 收入默认折叠的“连接详情”。固定映射、停用影响、收集条件等
  日常解释放入相邻的信息按钮。
- 复用已有 Tooltip，支持鼠标悬停、键盘聚焦、手机点按、Escape 关闭和视口边界
  处理。信息按钮必须具有可访问名称；关闭提示不能顺带关闭编辑弹窗。
- 展示已保存的 catch-all 目标和实际检查时间，提供“检查状态”。检查期间保留
  尚未保存的表单选择，检查完成后更新保存的观察结果。
- 当前外部 catch-all 风险、校验错误和写入结果未知必须直接显示，不能隐藏在
  信息提示中。保留 Collect 的后端校验，不自动改动用户策略。

## 错误国际化

- 保持 API 状态、稳定错误码、请求 ID 与后端契约不变。
- 增加共享的前端错误码翻译，覆盖域名/地址管理及公共的会话、权限、网络、
  存储故障。已知错误提供具体建议；未知错误使用当前语言的兜底文案，保留
  安全的错误码和请求 ID。前端已翻译的校验错误以显式类型标记，保留文件名
  和限制说明，不能与原始网络错误一起丢弃。
- 域名/地址管理、域名接入使用共享翻译；现有共用错误路径中仅为英文替换成
  通用提示的实现也改为复用该函数。
- 不直接将服务器或浏览器原始 message 当作英文界面文案。中英文词条一起更新。

## 验收与交付

- 单元/接口：Owner 隔离、五分钟冷却、并发去重、错误恢复、地址意图不变、
  批量并发上限与部分失败、HTTP 200 内部错误、已知与未知错误翻译。
- 浏览器：搜索/分页之外的批量检查、进度与重复操作、部分失败/无效响应、
  自动刷新时序与暂停恢复、编辑草稿、英文失败文案、信息提示和地址页刷新。
- 完成仓库 test/check/build、打包 dry-run，以及相关 Chromium 桌面/手机/窄屏、
  无障碍、WebKit、Firefox 验证。截图和运行记录保存在源码之外。
- SPEC 与实现通过独立任务分支提交，执行本地 Codex review。
  PRE 发布单独授权；完成功能 PRE 验收后再提 PR，等待当前 head 的两项机器人
  review 完成后按仓库流程合并。生产部署仍是独立步骤。

## 范围边界

不新增依赖、数据库迁移、全局轮询系统或自动刷新设置项；不修改邮件路由，
不发布生产、不发送真实测试邮件。
