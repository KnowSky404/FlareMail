# 邮箱导航性能与已读状态 Spec

状态：已实现；验收范围为隔离本地 Worker、D1/R2 和合成邮件。未发布 Preview 或生产，未执行远程迁移。

## 问题与核实

1. 文件夹和分类首次访问需要请求；旧实现再次访问仍重新请求并显示整块骨架，造成明显停顿。切换路径存在重复刷新入口。本地测得分类请求约 59–78 ms，因此本地证据支持客户端等待策略问题，不能据此判定生产请求延迟。
2. 侧栏收件箱徽标使用 `inboxCount`（全部未归档收件），而服务端已有 `unreadCount`。本地 fixture 的旧徽标为 48，实际未读为 26。
3. 普通点击才写入已读，工作区 `?message=` 与独立阅读页未统一处理。旧状态写入同时覆盖 read/starred，并发标记已读和加星会丢失一个字段。
4. 统计查询对相同邮件集合反复扫描；收件列表无投递筛选时仍连接出站投递表。SSR 存在可并行的读取。

## 产品行为

- 默认全宽列表、分栏、手机阅读页和独立链接共用已读规则：收件邮件真正进入可见阅读区域时自动标为已读。列表选中但详情隐藏、分类预加载、仅勾选、发件和草稿均不触发。
- 每次打开只自动标记一次。阅读期间手动标为未读后保持未读；关闭再打开可以再次自动标为已读。操作仅针对当前邮件，不扩展到整个会话。
- 桌面侧栏和手机导航的收件箱徽标显示当前 Owner 或所选域名/地址内未删除、未归档收件的未读总数；独立于分类、搜索、列表页和未读/星标筛选。零值不显示数字，超过 99 显示 `99+`；文件夹标题总数保留原语义。
- 状态变化立即更新行、详情和已知范围的未读徽标。正文加载独立于状态写入；迟到响应不得抢回阅读选择或覆盖后来的用户意图。

## 导航与缓存

- 缓存只存当前认证会话的内存，最多 16 个视图，LRU 淘汰，30 秒新鲜期。键包括文件夹、分类、标准化搜索、状态筛选、域名/地址、标签和 page limit。
- 返回新鲜视图直接显示已加载的页、追加邮件和游标，不发列表请求；过期或失效视图立即显示缓存并后台刷新。首次无缓存视图才显示骨架。后台失败保留列表并提供重试。
- 保留各视图滚动位置，阅读返回恢复焦点。URL 是导航状态来源；非空搜索输入合并为 250 ms 延迟。相同在途请求去重，新导航取消旧请求并检查响应代次。
- 手动刷新、状态/分类/标签/草稿/发送/归档/垃圾箱变化以及跨标签页通知使缓存失效。已读/星标先修补已缓存行，筛选不再匹配的行从对应页移除，再按需要重新拉取。
- 登出、认证失效和重新登录清空页面缓存、统计缓存和旧请求。旧认证代次的响应和排队写入不能应用到新会话。

## 服务端与 API

- 新增 `GET /api/workspace/mailbox/metrics?identity=address:<id>|domain:<id>`，响应包含 `metrics` 和 `metricsScope.identityFilter`，不返回邮件列表或正文。
- `PATCH /api/workspace/messages/:id/flags` 支持同样的可选 `identity`，用于返回统计范围。目标邮件仍以 Owner 权限校验，允许阅读当前分类之外的合法深链。未知或外部身份在写入前拒绝；无身份参数兼容原调用。
- PATCH 至少提供一个布尔 `read` 或 `starred`，只写提供的字段，响应正文为空。所有 GET 均不修改已读状态。
- 工作区邮件使用部分字段 UPDATE；入站状态原子 UPSERT 保留未提供字段、归档和删除状态，并拒绝复活已删除邮件。客户端每封邮件串行写入，以字段版本协调确认/失败回滚；批量已读操作先等此前单封状态队列结束。
- 统计以每来源一次条件聚合替代反复子查询。无投递筛选的 inbox 查询去掉出站连接；分页后的页不重复 window count，首屏总数在客户端追加时保留。SSR 共享一次统计读取，并行加载独立身份和页面。
- 已认证的列表、统计和状态请求提供 `Server-Timing`（可用阶段及 total）；日志仅记录操作类型、requestId、状态码和耗时，不记录地址、查询、邮件 ID 或正文。

## 验收条件

| 场景 | 预期 |
| --- | --- |
| 首次分类、快速连续切换 | 首次正常加载，迟到旧分类响应不覆盖新分类 |
| 返回新鲜分类/文件夹、追加后返回 | 列表立即显示，无列表请求，追加结果和游标保留 |
| 过期缓存、后台请求失败 | 旧列表可用，展示刷新/失败状态并可重试 |
| 地址 A/B、分类、搜索组合 | 内容隔离，徽标仅随身份范围和邮件状态变化 |
| 列表隐藏详情、工作区/独立深链、分栏 | 隐藏不读，可见收件自动读，每次打开一次 |
| 手动未读、并发读/星、迟到响应、失败 | 后来意图保留，独立字段不丢失，正文/选择不被覆盖 |
| 外部 Owner、无认证、非法请求、已删除邮件 | 拒绝访问/写入，不泄露正文，不恢复已删除状态 |
| 手机、320 px 窄屏、键盘导航 | 徽标语义一致、无横向溢出、分类焦点可用 |

## 本地验证记录

- `bun run test`：623 项通过；覆盖缓存 TTL/LRU、去重/失效/迟到响应、逐字段回滚、认证代次、两种邮件来源并发更新、草稿只读状态请求不覆盖星标、统计身份隔离及 API 认证/非法参数/删除边界。
- 查询对比：Bun SQLite 内存库，5,000 封工作区邮件、5,000 封入站邮件及其状态；同库、同 Owner、预热 5 次、测量 30 次。结果一致。旧统计中位数 17.74 ms、p95 32.70 ms；新统计中位数 10.40 ms、p95 14.66 ms。此处为本机合成查询微基准，不代表 Cloudflare D1 或生产请求 p95。
- 浏览器验收使用固定合成身份、隔离本地 D1/R2。截图和 trace 保存在本地测试产物中；Linux 录像工具收尾停滞，本轮关闭录像。Chromium 桌面邮件工作流 15 项通过、390 px 手机 12 项通过、320 px 窄屏 12 项通过；手机/窄屏共 8 项桌面专用用例按条件跳过。最终构建额外复验桌面/手机各 5 项，包含缓存滚动、登录不自动打开首封邮件、身份范围徽标、状态响应与新文件夹请求竞态，以及 WCAG 2.1 AA、触控尺寸和浅深色主要邮件流程。
- WebKit 桌面导航/阅读和偏好键盘操作 2 项通过，Firefox 桌面阅读/搜索焦点 2 项通过。WebKit 既有偏好焦点断言首次失败，同一构建重试通过，未改动偏好组件或放宽断言。Linux WebKit 结果不代表真实 Safari/iOS。
- 最终 `bun run check` 与 `bun run build` 通过；浏览器验证后补充草稿部分字段边界并重跑 623 项测试与类型/构建门禁。未运行 CI、远程 Preview、生产部署、远程迁移或真实供应商验收。

性能数字只代表对应环境，不构成生产 p95 或真实邮件供应商验收。

## 兼容与发布

没有新增依赖、D1 migration、绑定或 schema 版本变化。仍要求当前 schema 28（包括既有分类迁移）。缓存每次重新加载页面即消失；外部新增邮件可通过刷新或过期视图重新进入获取。跨标签页只发送失效通知，不传播邮件内容。远程请求耗时需在授权的环境中通过 `Server-Timing` 和浏览器 Network 另行核实。
