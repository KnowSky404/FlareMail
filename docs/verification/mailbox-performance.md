# 邮箱交互性能验证

2026-11-23 核对远端 `main` 为 `92fd8c84323a3c4aee71c7a47bd022b51fdc87ce`。原检出干净。测量与实现使用从该提交创建的独立本地 `perf/mailbox-interactions` worktree。

## 复现

使用 Bun 1.4.4、cf 1.0.0-rc.1、Ubuntu 24.04 arm64 和 Chromium 156。按 [开发指南](../DEVELOPMENT.md#diagnose-mailbox-navigation) 安装锁定依赖与 Playwright 浏览器。将两个测量脚本复制到基线 worktree 的相同相对路径，在两个源码版本上分别使用独立的本地临时目录和端口。启动前确认使用已签入的本地绑定及 demo provider。

```bash
task_tmp=$(mktemp -d)
export TMPDIR="$task_tmp" TMP="$task_tmp" TEMP="$task_tmp"
bun scripts/e2e/start-local.ts --port 4188
```

在另一终端指定刚启动的 Worker 端口，再分别运行两个测量脚本。D1 脚本会替换该实例的合成邮箱数据，所以在浏览器测量之后运行。复测时重新启动隔离实例恢复默认 fixture。文件应保存到任务证据目录。

```bash
perf_origin=http://127.0.0.1:4188
FLAREMAIL_PERF_ORIGIN="$perf_origin" FLAREMAIL_PERF_SAMPLES=12 bun scripts/e2e/measure-mailbox.ts > browser.json
FLAREMAIL_PERF_ORIGIN="$perf_origin" FLAREMAIL_PERF_REPLACE_E2E_MAIL=yes FLAREMAIL_PERF_SAMPLES=10 \
  bun scripts/e2e/measure-mailbox-d1.ts > d1.json
```

- 浏览器每个网络条件 12 次。1280 × 900，浏览器上下文和 HTTP 缓存每次重建，登录后测量首次工作台文档、首次打开各视图和会话内缓存命中。慢网用 Chromium CDP 注入 150 ms 延迟、下行 1.6 Mbps、上行 0.75 Mbps。服务器使用同一台本地机器的 Worker 与 D1/R2 模拟器。
- 浏览器记录点击或输入事件至首个可见反馈、目标内容或成功通知的时间，分别记录 HTTP 请求、TTFB、完成耗时、响应传输量及可用的 `Server-Timing`。记录 Chromium 的任务、脚本、样式和布局时长、Long Tasks、DOM 节点数及首个内容绘制。以浏览器帧内的 DOM 可见性作为交互反馈的近似。
- D1 矩阵包含 0、100、1,000、10,000 封邮件，混合入站来源、工作区收发、三个地址及两个域名，并含归档、删除、未读、星标与标签。查询覆盖各文件夹、身份、分类、FTS、游标、详情和标记操作。D1 矩阵里的草稿箱为空，含草稿的加载由 Chromium 的首次草稿箱流程覆盖。主要列表与聚合项分开记录第一次读取与 10 次重复样本，在本地 Local Explorer 关联请求和 D1 语句。Inbox 第二页、详情和标记操作只记录重复样本。带 SQL 的首轮 trace 用于生成 `EXPLAIN QUERY PLAN`，以占位参数查看计划形态。
- 所有统计来自本地 fixture。小样本 p95 按 nearest rank 计算，接近单次最大值，用于排查尾部波动。浏览器冷上下文测量包含 SSR 与资源传输，Worker 已被健康检查和登录请求唤起。D1 日期和耗时量化粒度以本地运行时为准。

## 发现与选择

| 优先级 | 入口 | 验证与处理 |
| --- | --- | --- |
| P1 | `hooks.server.ts`、`workspace/session.ts`、`db/sessions.ts` | 基线活跃请求重复读取 schema，分开读 Owner 和会话，每次执行通常写零行的 touch。复用本请求已通过的 schema 检查，在 token 查询内读取当前 Owner。SQL 决定是否需要 touch，更新仍带时间窗及撤销/到期条件。 |
| P1 | `+page.svelte`、`mailbox-controller.ts` | 单行归档的写入和列表回读串联，确认提示等待第二个网络往返。确认写入后按返回的归档状态更新已知行、失效旧缓存，并在身份与快照一致时使用返回计数。回读保留用于重建分页边界和补齐记录。 |
| P1 | `MessageListItem.svelte` | 40 行缓存收件箱无列表请求，脚本仍占主要时间。每行重复构造日期格式化器。按应用 locale 复用两种 formatter，保留本地日期边界和语言切换。 |
| P1 后续 | `db/inbox-categories.ts`、`db/mailbox.ts` | 10,000 封未存分类的 fixture 中，`primary` 分类需要对两种来源运行规则 fallback 并计总数。两条 SQL 已命中 Owner/文件夹相关索引，单次样本合计约 286 ms SQL 时间。需用有代表性的历史分类覆盖率决定回填或索引方案。 |
| P2 后续 | `getMailboxMetrics()`、`loadMailboxPage()` | 万封邮件的全局精确聚合约读 19,749 行，普通首屏合计约读 22,045 行。游标第二页免算聚合，约读 2,345 行。搜索在高命中率 fixture 约读 100,759 行，计划含 FTS 虚拟表与排序。合成数据不足以决定新索引或修改精确统计。 |
| P2 后续 | `+page.server.ts`、`+page.svelte`、`MailIdentityManager.svelte` | SSR 已复用统计并行加载独立数据。首次设置及域名表格在慢网仍受代码分包和随后读取资源列表影响。首次地址切换复用已加载表格数据。已保存资源先于手动诊断显示。自动供应商检查沿用可见性、冷却期、并发限额和卸载失效。 |
| P2 后续 | `MessageDetail.svelte`、`MailAiPanel.svelte` | 读取已测样本通常有正文、AI 状态和自动已读三个请求，缓存再打开时仍读 AI 状态，正文缓存命中不重复加载。后续评估状态读取何时可延后，同时保留正文、附件和 HTML 权限。 |

认证结果始终由每个请求针对当前 D1 Owner、有效期、撤销状态、认证方式和 Access principal 查询得出。Access 配置里的 Owner 必须匹配，已有 JWKS 冷却 30 秒、缓存 5 分钟及最多 4 组配置的边界。每次 Access 请求均验证签名和 claims，密钥不可用时拒绝。此次将 Access 验签计入 `auth` 阶段，真实远端 JWKS 延迟需要独立测量。没有新增 schema 或 dependency，也没有缓存 Owner 或会话授权。

浏览器列表缓存继续沿用 30 秒新鲜期、会话内存、分页与筛选键以及迟到响应隔离。单封归档和取消归档根据 D1 写入结果确认成功。若写入时邮件已经离开操作范围，显示现有错误提示并重新读取。后台重读失败时保留已确认列表状态或显示现有重试入口。单个优化可通过回退相应代码恢复原路径，无数据库回退步骤。生产、远程迁移与真实发信遵循各自的授权流程。

搜索测量结果区域反馈，设置与域名的反馈包含管理页骨架。前后对比均为本地模拟，生产认证邮箱 API 的 1 秒 p95 目标还需通过真实流量验证。

独立的 Access 校验测量在 Bun 中每组验证 30 次。使用即时模拟 JWKS 时，冷验证 p50 / p95 为 0.37 / 1.13 ms，暖验证为 0.16 / 1.16 ms。给 JWKS 注入 150 ms 后，分别为 150.81 / 153.98 ms 和 0.15 / 0.24 ms。每个冷验证取一次密钥，暖验证期间没有取密钥，所有样本均完成服务端签名校验。此处使用模拟密钥服务，无真实 Access 链路结论。
